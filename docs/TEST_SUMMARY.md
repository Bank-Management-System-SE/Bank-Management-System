### TC-SEC-02 — PIN secrecy and masking

The executed specification confirms that:

- `accounts.dat` contains a 64-character hash rather than the plaintext PIN.
- No PIN or hash was found in `txns.dat` or `audit.log`.
- The PIN was not present in captured console output.
- **Interactive WSL terminal verification:** During account creation and customer login, PIN characters were not echoed or displayed while typing.
- Both account creation and customer login completed successfully.

**Status: PASS**

The prior specification also says Windows code prints `*` for each key. That statement is a reported code behaviour, not proof that the interactive test was performed.

## 5. Transfer interruption verification

The separate transfer integrity report records three process-interruption runs:
- 120 processes killed in total (40 per run).
- 0 runs with inconsistent balances.
- 205,373 transfer ledger rows written.
- 189 checks where the last ledger row lagged.

This supports the balance-consistency result for the tested interruption scenarios. It does **not** establish atomicity between account-balance persistence and transaction-ledger append. The ledger limitation remains documented in `docs/TRANSFER_INTEGRITY.md` and `DEVIATIONS.md`.
